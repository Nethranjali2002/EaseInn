=========================================================
EASEINN PMS - FRESHER DEVELOPER SETUP GUIDE
=========================================================

Welcome to the EaseInn team! This guide will walk you through setting up the EaseInn Property Management System on your local machine from scratch.

---------------------------------------------------------
1. PREREQUISITES (What you need installed)
---------------------------------------------------------
Before starting, ensure you have the following installed on your machine:
1. Node.js (v16.x or higher) - For the backend API
2. MongoDB - Either a local instance (MongoDB Compass) or a MongoDB Atlas URI string
3. Flutter SDK (v3.19.x or higher) - For the Web Admin and Mobile Apps
4. Git - For version control
5. Visual Studio Code (or your preferred IDE)

---------------------------------------------------------
2. UPDATE YOUR LOCAL REPOSITORY (IMPORTANT!)
---------------------------------------------------------
Since the project folder structure has been heavily reorganized, you MUST sync your local repository before continuing.

1. Open your terminal inside your existing EaseInn project folder.
2. Clean your local state and pull the latest changes:
   > git fetch origin
   > git reset --hard origin/main
   > git clean -fd

(Warning: This will wipe out any uncommitted local changes and sync you perfectly with the new structure).

---------------------------------------------------------
3. SETUP THE BACKEND (Node.js API)
---------------------------------------------------------
The backend controls the database, business logic, and file uploads.

1. Navigate to the backend folder:
   > cd backend

2. Install all Node modules/dependencies:
   > npm install

3. Configure Environment Variables:
   Create a new file named `.env` inside the `backend/` folder and paste the following baseline config:
   
   PORT=3000
   MONGODB_URI=mongodb://localhost:27017/easeinn
   JWT_SECRET=easeinn_super_secret_key_change_in_production
   JWT_EXPIRES_IN=1d

   (Note: If you use MongoDB Atlas, replace the MONGODB_URI with your remote connection string).

4. Start the backend development server:
   > npm run dev

   You should see a console message saying the server is running on port 3000 and connected to MongoDB. Keep this terminal window open!

---------------------------------------------------------
4. SETUP THE FRONTEND WEB (Admin Dashboard)
---------------------------------------------------------
This is the portal used by Admins and Managers to handle operations.

1. Open a new terminal window and navigate to the web frontend folder:
   > cd frontend/web

2. Fetch Flutter packages:
   > flutter pub get

3. Run the Web Application on Google Chrome:
   > flutter run -d chrome

   Chrome will open and display the EaseInn Web Dashboard. By default, it communicates with the local backend running on port 3000.

---------------------------------------------------------
5. SETUP THE MOBILE APP (Staff & Tasks)
---------------------------------------------------------
This is the mobile application used by the staff for assigned tasks.

1. Open a new terminal window and navigate to the mobile folder:
   > cd frontend/mobile

2. Fetch Flutter packages:
   > flutter pub get

3. Run the Mobile App (Make sure you have an Android/iOS emulator running, or a connected physical device):
   > flutter run

---------------------------------------------------------
6. TROUBLESHOOTING & TIPS
---------------------------------------------------------
- Shared Logic: If you ever make changes to core data models or API clients, note that both the Web and Mobile apps share logic from the `frontend/shared/` folder.
- Blank Screen on Web: If Flutter Web gives you a blank screen or CORS error, ensure your backend server is actually running on port 3000 and you haven't closed its terminal window.
- Database Setup: If you start with a blank database, you may need to register an initial Admin user via the backend API or a registration screen to log in to the dashboard.
---------------------------------------------------------
7. BACKEND ARCHITECTURE & FOLDERS (Quick Reference)
---------------------------------------------------------
The backend follows the Controller-Service-Model pattern. You can easily search for these terms in the codebase:

* routes/ (The Front Desk)
  Holds all the API URLs (endpoints). When the frontend sends a request, it hits the route first and is directed to the right controller.

* middlewares/ (The Security Guards)
  Runs before the controller. For example, auth.middleware.js checks if the user has a valid login token (JWT).

* controllers/ (The Managers)
  Receives the request from the route, extracts the data (req.body), passes it to the Service layer to do the work, and sends the final response back to the user.

* services/ (The Brains / Heavy Lifters)
  Contains the actual business logic. It checks rules, does math, and decides if an operation is allowed before talking to the database.

* models/ (The Database Blueprints)
  Defines the MongoDB schemas. Ensures data matches the exact format (e.g., a room MUST have a capacity number) before saving.

* utils/ (The Helpers)
  Reusable helper functions like codeGenerator.js (which atomically generates sequential IDs like RM-0001).

Happy Coding!
